// ============================================================================
//  titles.txt - SISTEMA DE FALAS E DOCUMENTOS DO ROAD TO NOWHERE
//  Criado por Hermes e Hidrocarboneto.
//
//  COMO FUNCIONA (orientações para uso futuro):
//  ----------------------------------------------------------------------------
//  Este é o ARQUIVO CENTRAL de mensagens do jogo. Ele não fica no mapa:
//  as entidades no mapa guardam apenas o NOME da mensagem, e o texto
//  (com formatação) é buscado aqui pelo client.
//
//  FLUXO:
//    entidade no mapa (ex: env_message ou game_text)
//      -> keyvalue "message" = "#NOME_DA_MENSAGEM" (com # na frente!)
//      -> server envia "HudText" ao client
//      -> client busca NOME_DA_MENSAGEM neste arquivo
//      -> desenha na tela com os atributos abaixo
//
//  FORMATO DE CADA MENSAGEM:
//    (linhas com // no início são comentários e são ignoradas)
//
//    $position x y      -> posição na tela. x e y vão de 0 a 1
//                          (0 = esquerda/topo, 1 = direita/fundo).
//                          -1 centraliza no eixo.
//                          NEGATIVO no y = DISTÂNCIA DO FUNDO:
//                          y -0.1 = 10% acima do fundo (ideal p/ legenda).
//    $effect 0..2       -> 0 = fade in/out | 1 = flicker (creditos)
//                          2 = escrever letra por letra (scan)
//    $color  R G B      -> cor do TÍTULO (linha 1) - 0 a 255
//    $color2 R G B      -> cor da MENSAGEM (linhas 2 em diante)
//    $fadein  seg       -> tempo de fade-in (ou tempo por caractere no effect 2)
//    $fadeout seg       -> tempo de fade-out
//    $holdtime seg      -> tempo que fica na tela
//
//    NOME_DA_MENSAGEM   <- nome usado pela entidade (SEM # aqui)
//    {
//    Linha 1 do texto   <- TÍTULO (cor = $color)
//    Linha 2 do texto   <- MENSAGEM (cor = $color2)
//    }
//
//  SUBSTITUIÇÃO AUTOMÁTICA:
//    %player_name% no texto é trocado pelo nome do jogador (feito no server).
//
//  QUEBRA DE LINHA:
//    Cada linha dentro das chaves { } vira uma linha na tela.
//    Linha 1 = título (cor $color), linhas seguintes = mensagem ($color2).
//
//  FONTE:
//    O HUD usa a fonte bitmap global do engine (gfx/creditsfont.fnt) POR
//    PADRÃO - isso não muda a menos que você use $font (ver abaixo).
//
//  DICAS:
//    - Mensagem com # na frente (ex: "#Doutor_Intro") busca aqui.
//    - Texto sem # é exibido literalmente (com %player_name% e \n funcionando).
//    - Para legenda estilo filme: $position -1 -0.1 (centralizada no fundo).
// ============================================================================


// ============================================================================
//  FONTE E TAMANHO CUSTOM ($font / $fontsize) - RTN
//  ----------------------------------------------------------------------------
//  Por padrão toda mensagem usa a fonte fixa do engine (gfx/creditsfont.fnt),
//  desenhada num tamanho ÚNICO que não dá pra mudar - o engine não tem
//  parâmetro de tamanho nem de fonte na função que desenha cada letra
//  (pfnDrawCharacter). Pra ter TAMANHO configurável e FONTE escolhível por
//  mensagem (ex.: título de "episódio" grande, com fonte diferente), o RTN
//  ganhou um sistema PRÓPRIO de fonte bitmap, independente do engine:
//
//    $font <nome_curto>   -> ativa a fonte custom pro bloco INTEIRO (título
//                            E mensagem). <nome_curto> é o nome usado ao
//                            gerar a fonte com utils/gen_titlefont.py -
//                            ex.: "kirkwood" (fonte cplkirkwood.ttf, já
//                            incluída no projeto - ver abaixo como gerar
//                            outra fonte a partir de um .ttf).
//    $fontsize <px>       -> tamanho da fonte custom NA TELA, em pixels de
//                            altura de linha. SÓ TEM EFEITO junto com $font
//                            no mesmo bloco - não existe como aumentar a
//                            fonte padrão do engine, então $fontsize sozinho
//                            (sem $font) é ignorado. Sem $fontsize, mas COM
//                            $font, usa o tamanho "natural" da fonte (o
//                            tamanho em que o atlas foi gerado - 128px).
//
//  NÃO SÃO PERSISTENTES: assim como $position/$color/$effect/etc., $font e
//  $fontsize valem só pro bloco em que aparecem. Se a próxima mensagem não
//  repetir $font, ela volta a usar a fonte padrão do engine automaticamente -
//  não precisa "desligar" nada.
//
//  COMO GERAR UMA FONTE NOVA A PARTIR DE UM .ttf:
//    pip install Pillow      (uma vez só)
//    python3 utils/gen_titlefont.py minhafonte.ttf nome_curto
//  Isso cria:
//    game_dir/sprites/fonts/nome_curto.spr   (atlas com as letras, imagem)
//    game_dir/fonts/nome_curto.rtnfont       (métricas - onde cada letra
//                                              está no atlas e quanto espaço
//                                              ela ocupa)
//  Depois é só usar "$font nome_curto" em qualquer bloco deste arquivo.
//
//  IMPLEMENTAÇÃO (pra quem for mexer): client/hud_titlefont.h/.cpp carregam
//  o atlas (.spr) e as métricas (.rtnfont), e um parser próprio (bem mais
//  simples que o do engine) lê ESTE ARQUIVO de novo só pra achar as linhas
//  $font/$fontsize de cada bloco - porque client_textmessage_t (a struct que
//  o engine preenche com o resto dos dados de cada mensagem) é uma struct
//  fixa do engine, sem campo de fonte nem tamanho, e não dá pra estender.
//  O desenho de cada letra usa DrawSpriteAsPoly (client/render/tri.cpp),
//  recortando o glifo certo do atlas e desenhando do tamanho pedido - sem
//  isso, client/message.cpp usa TextMessageDrawChar como sempre (fonte do
//  engine, comportamento 100% igual ao de antes desta feature).
//
//  Exemplo (título de episódio, fonte grande):
//    $position -1 -1
//    $effect 0
//    $color 255 255 255
//    $color2 200 200 200
//    $fadein 1.0
//    $fadeout 1.0
//    $holdtime 4
//    $font kirkwood
//    $fontsize 96
//    Episodio_01
//    {
//    CAPITULO UM
//    A Estrada Sem Volta
//    }
// ============================================================================


// ============================================================================
//  EXEMPLO 1 - Fala de NPC (legenda no canto inferior, centralizada)
//  Uso no mapa: env_message com message = "#Doutor_Intro"
// ============================================================================
$position -1 -0.1
$effect 0
$color 255 200 0
$color2 255 255 255
$fadein 0.3
$fadeout 0.5
$holdtime 4
Doutor_Intro
{
Dr. Freeman:
Bem-vindo a Black Mesa, %player_name%.
Espero que goste do trabalho.
}


// ============================================================================

// ============================================================================
//  PICKUP MESSAGES (RTN F10 - automatico ao pegar municao)
//  O server envia o nome do ammo via AmmoPickup; o client monta "!<nome>"
//  e busca aqui. Sem a entrada, o fallback mostra o texto cru (feio) -
//  entao crie uma entrada para cada tipo de municao do mod.
//  Local: canto inferior-esquerdo, discreto (estilo Tarkov).
//
//  "%d" NO TEXTO -> QUANTIDADE RECEBIDA (Paranoia 2 style):
//  O client troca a primeira ocorrencia de "%d" pela quantidade real de
//  municao do pickup (client/ammo.cpp::MsgFunc_AmmoPickup passa o numero,
//  client/message.cpp faz a troca). O contador PADRAO do sistema (numero
//  generico no canto inferior direito) foi desligado de proposito pra nao
//  duplicar a mensagem - essas entradas aqui sao a UNICA notificacao de
//  pickup de municao agora. "%d" e opcional: sem ele, so mostra o texto
//  fixo, igual antes.
// ============================================================================
$position 0.02 -0.12
$effect 0
$color 255 200 0
$color2 255 255 255
$fadein 0.1
$fadeout 0.5
$holdtime 3
!9mm
{
+%d Municao 9mm
}
